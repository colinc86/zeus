# PC1 real pane captures

Captured with `python3 -B Zeus/App/Tests/Runtime/PC1LiveScreens.py --agent claude --native-updater --record`
and `--agent codex --record` / `--agent opencode --record`. Every screen and cursor metadata pair comes
from a private 120×40 tmux pane. All agent HOME/config folders are disposable, all model requests go to
a localhost fake, and no human config, credentials or default tmux server is used. The fixture helper
waits for its actual agent child to exit before removing scratch state.

Claude Code 2.1.299, Codex 0.162.1, OpenCode 1.18.31. ANSI is retained. Only the throwaway absolute root
path is replaced with `/FIXTURE`; UI text, colors, wrapping, timestamps and cursor positions are unchanged.

| Fixture | How the real screen was produced | Expected |
| --- | --- | --- |
| claude-idle | Finished a short localhost-model turn; composer empty | idle |
| claude-draft | Two lines deliberately pasted; no Enter | idle; both draft lines retained |
| claude-update-idle | Native updater succeeds on a copied installation inside the disposable HOME | idle |
| claude-scheduled-idle | A real native CronCreate one-shot fires; the scheduled turn returns no assistant text | idle |
| claude-update-working | Native work spinner while localhost response is held; installed-update badge is visible | working |
| claude-update-permission | Real Bash permission widget after update; no choice is sent | blocked; command and Yes/No parsed |
| codex-draft | Real native composer with deliberately unsent text | idle; draft retained |
| opencode-draft | Real centered home-screen composer with deliberately unsent text | idle; draft retained |

The update fixtures are genuine native updater notices, not edited captures or custom status-line copies.
The helper copies the installed Claude executable into its **own** HOME, enables updates there and starts
that copy. It never changes the user's executable. The original installed CLI remained 2.1.299 after the
probe. An empty scratch status line suppresses the usual interrupt hint, proving that active work detection
cannot rely on that hint. [Claude documents this status-line behavior](https://code.claude.com/docs/en/statusline).

**Native presentation limit:** 2.1.299 hides both the status line and the updater badge while its permission
widget is open. `claude-update-permission` preserves that actual capture rather than inventing a footer.
The regression also appends update/custom footer rows *in memory*, clearly separate from the recorded
fixture, to verify that a footer after confirmation controls cannot hide a permission or change its identity.

The scheduled-task line is generated by the native scheduler, not by a model imitating it. Its only later
output is Claude's native finished-turn summary; no assistant reply text follows it. See the
[scheduled-task documentation](https://code.claude.com/docs/en/scheduled-tasks) for session-local CronCreate.
